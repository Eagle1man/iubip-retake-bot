# iubip-retake-bot

MVP сервиса записи на пересдачу через бота MAX.

Заявка отдела: **T-1074**. План: `D:\itотдел\docs\plan-iubip-retake-bot-mvp.md`.
Решения и отклонения от плана: [DECISIONS.md](DECISIONS.md).

## Что это

Сквозной рабочий сценарий «студент записывается → преподаватель видит →
дирекция отмечает оплату → все получают уведомления», показываемый **без токена
MAX**: при `MOCK_MAX=true` сообщения уходят в `NotificationLog`, а чат живёт во
встроенном эмуляторе `/mock/`.

Стек (по ТЗ §3): Node 20 · TypeScript 5 strict · Fastify 4 · Zod 3 ·
PostgreSQL 16 · Prisma 5 · BullMQ 5 + Redis 7 · Vitest 2 · Docker Compose.
Клиент MAX — свой, на `fetch`, без SDK.

## Как показать демо за 5 минут (§12)

### Путь A — Docker

```bash
docker compose up --build
```

Контейнер сам накатывает миграции, прогоняет сид и поднимает приложение.
Проверка:

```bash
curl http://localhost:3000/healthz        # {"db":"ok","redis":"ok","mockMax":true}
docker compose logs app | grep DEEP_LINK  # токен для шага 3
```

Открыть **http://localhost:3000/mock/** — это эмулятор чата.

> На машине разработчика Docker Desktop нет, поэтому путь A написан по плану
> §15 и здесь не прогонялся. Проверенный локальный путь — ниже.

### Путь B — локально (проверен)

```powershell
npm install
Copy-Item .env.example .env    # и поправить DATABASE_URL/REDIS_URL под себя
npm run db:migrate
npm run db:seed                # печатает DEEP_LINK=rt_<дисциплина>_<сессия>
npm run dev                    # http://localhost:3000
```

Порт берётся из `.env`; если 3000 занят — `$env:PORT=3100; npm run dev`.

Для этого пути нужны поднятые Postgres 16 и Redis 7 (на этой машине — в WSL2,
скрипты `scripts/wsl-setup.sh`, `scripts/wsl-grant.sh`).

### Сценарий §12 — шаги и ожидаемые ответы

Эмулятор открывается на `http://localhost:3000/mock/`. Роли переключаются
кнопками **Студент (1001)** / **Преподаватель (2001)** / **Дирекция (3001)**;
уведомления от *других* ролей появляются после кнопки **Обновить**.

| # | Кто | Действие | Ожидаемый результат |
|---|---|---|---|
| 1 | — | `docker compose up --build`, дождаться `/healthz` | `{"db":"ok","redis":"ok","mockMax":true}` |
| 2 | — | открыть `http://localhost:3000/mock/` | чат с полем `userId` и кнопками ролей |
| 3 | студент `1001` | в поле payload вставить `DEEP_LINK` из логов, нажать **Отправить /start** | «Открытые сессии по дисциплине «Математический анализ»:» → кнопка сессии → ввести ФИО → ввести группу → **Всё верно** → «Вы записаны! Номер записи: B-…» + предложение чека → **Пропустить** → «Вы допущены к пересдаче… Чек к записи B-… не приложен.» |
| 4 | преподаватель `2001` | **Мои сессии** → **Список записавшихся** | «Записалось: …» и строка `ФИО · ГР-… · оплата: submitted · чек: нет` — **запись без чека видна** |
| 5 | дирекция `3001` | **Отметить оплату** → ввести `B-<номер из шага 3>` → **Оплачено** | «Запись B-…: оплата отмечена как «оплачено»»; у студента (`1001` → **Обновить**) — «Оплата по записи подтверждена.» |
| 6 | дирекция `3001` | **Импорт реестра** → вставить содержимое `prisma/fixtures/registry-demo.csv` → **Отправить реестр** | «Реестр обработан. Всего строк: 2 / Сопоставлено: 1 / Не сопоставлено: 1» и имя несопоставленной строки |
| 7 | дирекция `3001` | **Сменить аудиторию** → выбрать сессию → ввести новую аудиторию (напр. `Ауд-777`) | «Аудитория изменена. Уведомлений отправлено: N»; студенту после **Обновить** — «Аудитория изменена: теперь Ауд-777.» |
| 8 | преподаватель `2001` | **Мои сессии** → **Отменить** | «Сессия отменена. Уведомлений отправлено: N»; все записанные получают «Сессия отменена …», сессия уходит из открытых |
| 9 | — | выгрузка CSV | `curl -H "X-Service-Token: dev-service-token" http://localhost:3000/internal/export/bookings.csv` — все записи с полями и статусами |

Дополнительно, прямо из эмулятора: **Выгрузить CSV** у дирекции печатает ссылку
на ту же выгрузку.

### Ручной чеклист (§11.4)

| Шаг | Ожидаемый результат | Как проверить |
|---|---|---|
| `/healthz` без БД | `db:"fail"`, код 200 | остановить Postgres, повторить curl |
| запись без чека | запись `submitted` видна преподавателю | шаг 4 |
| после дедлайна регистрации | «Регистрация на эту сессию закрыта…», API → 410 | `POST /internal/bookings` с истёкшим `registrationDeadline` |
| вторая активная запись на дисциплину | «У вас уже есть активная запись…», API → 409 | integration `bookings.test.ts` |
| повтор того же `paymentToken` | `deduplicated:true`, вторая строка не создаётся | integration, шаг «тот же paymentToken повторно» |
| чек на другую запись слота | 409 `receipt_used_elsewhere` | integration `bookings.test.ts` |
| `MOCK_MAX=false` | `/mock/` → 404, `POST /mock/max/inject` → 404 | integration `api.status.test.ts` |
| без `X-Service-Token` | 401 | `curl` без заголовка на любой `/internal/*` |
| throttling | не больше 30 сообщений в минуту | integration `notifications.throttle.test.ts` (живой Redis) |

## Что здесь заглушка

- **Формат реестра** — временный `fio,amount,paid_at,purpose`; как придёт
  настоящий реестр от бухгалтерии, меняется только `src/domain/registry/csv.parser.ts`.
- **Макс в mock-режиме** — сообщения не уходят в сеть, а пишутся в `NotificationLog`.
- **Чек не проверяется** — сохраняется файл и `sha256`; сверки с платёжным
  сервисом нет.
- **Подпись вебхука** — сравнение заголовка с секретом как есть; реальный
  формат подписи MAX нужно подставить при боевом включении (§5 DECISIONS.md).
- **Оплаты** — фиксируются вручную дирекцией или импортом реестра; вебхук от
  платёжного сервиса в MVP не реализован.
- **Напоминания** — `REMINDERS_ENABLED=false`.

## Боевой режим

`MOCK_MAX=false` + `MAX_BOT_TOKEN` (+ `MAX_WEBHOOK_SECRET`), TLS-прокси —
`docker compose --profile prod up -d` (Caddy, `Caddyfile`).
Публикацию на production выполняет человек, не агент.
